
# AlgoLab — Planejamento do Projeto

## 1. Identificação

- **Projeto:** AlgoLab — Visualizador de Algoritmos
- **Objetivo:** Desenvolver uma aplicação web para apresentar algoritmos de ordenação e demonstrar visualmente seu funcionamento.
- **Gerente do projeto:** Edson Sá
- **Equipe:** Edson, Rafael, Ramon, Lucca e Jonatha.

## 2. Objetivo

Construir uma aplicação web que permita ao usuário conhecer algoritmos de ordenação, acompanhar demonstrações de sua execução e consultar informações sobre seu funcionamento e complexidade assintótica (Big O).

A aplicação deverá priorizar uma interface intuitiva, identidade visual consistente e organização do conteúdo.

## 3. Escopo do projeto

### Funcionalidades previstas

- Página inicial com apresentação do AlgoLab.
- Catálogo dos algoritmos disponíveis.
- Visualizador com seleção de algoritmos e demonstrações visuais.
- Página explicativa sobre complexidade de algoritmos.
- Página com informações sobre o projeto e sua equipe.
- Interface responsiva e compatível com navegadores atuais.

### Algoritmos contemplados

- Bubble Sort.
- Insertion Sort.

### Fora do escopo inicial

- Cadastro de usuários e autenticação.
- Armazenamento de perfis.
- Execução de códigos enviados pelos usuários.
- Ampliação do catálogo antes da conclusão das funcionalidades principais.
- Recursos avançados de animação que não sejam essenciais à proposta.

## 4. Organização da equipe e responsabilidades

| Integrante | Responsabilidade | Atividades |
|---|---|---|
| Edson | Gerenciamento e front-end | Organizar tarefas e cronograma, acompanhar o desenvolvimento, estruturar as páginas HTML e desenvolver o CSS. |
| Rafael | Apoio ao CSS | Auxiliar Edson na estilização das páginas, aplicação da identidade visual e ajustes de responsividade. |
| Ramon | Interface e componentes | Desenvolver componentes e interações da interface, além de integrar os controles ao funcionamento dos algoritmos. |
| Lucca | Lógica e algoritmos | Implementar os algoritmos, estruturar os estados e etapas de execução e disponibilizar os dados necessários à interface. |
| Jonatha | Documentação | Preparar e revisar o conteúdo informativo dos algoritmos, incluindo funcionamento e complexidade. |

**Observação:** as atividades de qualidade e testes não possuem um responsável exclusivo. A equipe deverá realizar a validação conjunta das funcionalidades e corrigir os problemas identificados durante a integração.

## 5. Fluxo de trabalho e controle de versão

- O GitHub será utilizado como repositório oficial do projeto.
- Cada integrante deverá trabalhar em uma branch própria ou de funcionalidade.
- Alterações não deverão ser realizadas diretamente na branch principal.
- As entregas deverão ser enviadas por Pull Requests para revisão e integração.
- Os commits deverão possuir mensagens objetivas e representar alterações coerentes.
- As tarefas deverão possuir responsáveis e entregas identificáveis.
- A equipe deverá manter comunicação sobre alterações que possam afetar a integração entre HTML, CSS e JavaScript.

## 6. Etapas e entregáveis

| Etapa | Entregável | Critério de conclusão |
|---|---|---|
| 1. Planejamento | Escopo e responsabilidades definidos | Equipe alinhada quanto às atividades. |
| 2. Estruturação | Repositório, pastas e páginas HTML | Estrutura inicial organizada. |
| 3. Desenvolvimento visual | CSS e identidade visual | Páginas estilizadas e responsivas. |
| 4. Desenvolvimento lógico | Algoritmos implementados | Lógica dos algoritmos disponível para integração. |
| 5. Integração | Interface conectada às funcionalidades | Seleção e demonstração dos algoritmos funcionando. |
| 6. Validação | Aplicação revisada pela equipe | Problemas identificados corrigidos. |
| 7. Publicação | Versão final disponibilizada | Aplicação acessível e link validado. |

## 7. Critérios de aceitação

- A aplicação apresenta as cinco páginas previstas.
- A navegação entre as páginas funciona corretamente.
- Os algoritmos previstos estão disponíveis no catálogo.
- O usuário consegue selecionar os algoritmos no visualizador.
- As demonstrações correspondem aos algoritmos selecionados.
- As informações de complexidade estão coerentes com as implementações.
- A interface mantém a identidade visual e apresenta comportamento responsivo.
- A equipe realiza a validação da versão final antes da publicação.

## 8. Riscos e medidas preventivas

| Risco | Medida preventiva |
|---|---|
| Atraso na integração entre interface e lógica | Definir previamente como os dados dos algoritmos serão utilizados pelo front-end. |
| Incompatibilidade entre HTML, CSS e JavaScript | Manter comunicação entre os responsáveis pelas diferentes partes. |
| Alterações conflitantes no Git | Utilizar branches e Pull Requests. |
| Crescimento desnecessário do escopo | Priorizar as funcionalidades previstas para a primeira versão. |
| Problemas identificados próximo à entrega | Realizar validações durante o desenvolvimento e antes da publicação. |
